Hook · activation of prior knowledge
Sound familiar?
"Has anyone ever needed to rank salespeople by revenue - and ended up with a subquery inside a subquery inside another subquery?"
select * from (select * from (select...)) where rank = 1 order by total desc limit 3
There is a better way. Window functions let you rank, compare and calculate across rows without collapsing your data the way GROUP BY does.

Today you will never write a nested subquery for ranking again.
Core concept
What is a window function?
It performs a calculation across a set of rows - without collapsing them into one.
ROW_NUMBER()
Assigns a unique number to each row. Use it to deduplicate or get the latest record per customer.
ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY order_date DESC)
RANK()
Ranks rows within a group. Ties get the same rank. Use it for league tables and top-N queries.
RANK() OVER (PARTITION BY region ORDER BY revenue DESC)
LAG()
Looks back at the previous row. Use it for period over period comparisons - this month vs last month.
LAG(revenue, 1) OVER (ORDER BY month)
SUM() OVER()
Calculates a running total without collapsing rows. Every row keeps its own data plus the cumulative sum.
SUM(revenue) OVER (ORDER BY order_date ROWS UNBOUNDED PRECEDING)
Live demo
Four functions, one dataset
Watch, then you will try it yourself.
SQL editor - orders dataset
-- ROW_NUMBER: get each customer's most recent order
SELECT customer_id, order_date, order_total,
  ROW_NUMBER() OVER (PARTITION BY customer_id
                 ORDER BY order_date DESC) AS row_num
FROM orders;
 
-- RANK: top salespeople by region
SELECT salesperson, region, revenue,
  RANK() OVER (PARTITION BY region ORDER BY revenue DESC) AS rank
FROM sales;
 
-- LAG: compare this month to last month
SELECT month, revenue,
  LAG(revenue, 1) OVER (ORDER BY month) AS prev_month
FROM monthly_revenue;
 
-- SUM OVER: running total
SELECT order_date, order_total,
  SUM(order_total) OVER (ORDER BY order_date) AS running_total
FROM orders;

Check for understanding
Quick check
Pick the best answer - no pressure.
You need to find the most recent order for each customer. Two customers placed orders on the same day. Which function gives each row a unique number regardless of ties?
A
RANK() - it handles ties automatically
B
ROW_NUMBER() - it always assigns a unique number even with ties
C
LAG() - it looks at the previous row to find duplicates
D
SUM() OVER() - it adds up the rows to find the latest
✓ B is correct. ROW_NUMBER always assigns a unique sequential number - even when rows are tied on the ORDER BY value. RANK would give both tied rows the same number, which would mean two rows per customer instead of one.
Summary and next steps
What you can do now
✓Use ROW_NUMBER to deduplicate and find the latest record per group
✓Use RANK to build league tables and top-N queries per partition
✓Use LAG for period over period comparisons without a self-join
✓Use SUM OVER to calculate running totals while keeping row detail
